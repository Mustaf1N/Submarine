## 4. Монтажные приёмы в ролике

* камера: push-in 105–115 % с easing, «дыхательный» дрейф и микро-шейк (амплитуда ≤ 0.5 %), всё через `zoompan` с выражениями по кадру;
* склейки: на каждом стыке — растворение 0.22 с из последнего кадра предыдущего плана (картинка не рвётся, нет «вспышек» между планами); первый кадр ролика проявляется из чёрного за 0.12 с;
* анти-«вспышка»: план короче 0.9 с на экране не выводится — остаётся только основной кусок, огрызки у вырезок уходят в вырезанное;
* графика: открывающая/финальная карточки, 6 кинетических титров глав, плашки-выноски с линией-указателем и виньеткой объекта, freeze-frame [САПФИР];
* звук: музыка 100 BPM (синтезирована), SFX на переходах и наградах, ducking музыки −8 дБ в защищённых окнах и просадка под карточками;
* цвет: единый грейд на обе записи (контраст 1.07, насыщенность 1.08, unsharp 0.45), у тёмной арены дополнительно gamma 1.45;
* 4:3 вторая запись разложена в 16:9: картинка 1440×1080 по центру + размытый затемнённый фон по бокам, хотбар не обрезается.

## 6. Как пересобрать

```bash
mkdir -p raw && cp 'Minecraft 2026.11.23 - 18.27.09.01.mp4' raw/A.mp4 \
                     && cp 'Minecraft 2026.11.26 - 03.19.04.01.mp4' raw/B.mp4
python3 edit/analyze.py        # покадровый анализ 0.2 с → edit/analysis/
python3 edit/timeline.py       # EDL 12:00–13:30 → edit/timeline.json
python3 edit/render.py --all   # рендер → deliver/HoweMine_review_1080p60.mp4
python3 edit/qc.py             # контактные листы, склейки, blackdetect/freezedetect
python3 edit/report.py         # этот отчёт + docs/howemine.srt
```

Сегменты кэшируются по хэшу параметров (`work/cache/`), поэтому пересборка после правки одного участка занимает секунды.

## Ограничение среды (честно)

Исходные записи не удалось скачать в эту среду: `drive.google.com` недоступен из
песочницы, а коннектор Google Drive отдаёт файлы только до 100 МБ (записи — 479 МБ
и 149 МБ). Поэтому цифры выше — результат **self-test на синтетических двойниках**
записей: проверяется механика (анализ кадров → защищённые окна → подгонка
длительности → рендер → QC), а не содержание реальных записей.

На реальных файлах те же правила дадут реальные таймкоды, а защищённые окна будут
полной длины: кейсы ≈ 27 с, лут ≈ 76 с, арена ≈ 60 с.

Чтобы получить готовый 12-минутный ролик: положите записи в `raw/A.mp4` и
`raw/B.mp4` (или оставьте «сырые» имена из OBS — пайплайн найдёт их сам) и
выполните `bash run_all.sh`.

## Где готовый файл

* `deliver/HoweMine_review_1080p60.mp4` — один файл (104 МБ);
* `deliver/parts/` — две части ≤100 МБ (56 + 47 МБ) + `manifest.json` с SHA-256;
* `deliver/install_windows.bat` — батник для чистой Windows: ставит Python и
  ffmpeg, качает части, проверяет хэши, склеивает без перекодирования и кладёт
  ролик в `%USERPROFILE%\Downloads\HoweMine`;
* публичные ссылки Dropbox: один файл, папка частей, батник (см. README).

GitHub Release опубликовать из этой среды не удалось: токен не имеет права
создавать репозитории (`createRepository`), а `uploads.github.com` не отвечает (EOF).
